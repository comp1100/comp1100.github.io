# Marking instructions (all iterations)

## Spreadsheet setup

- Copy the first worksheet and rename it `Team XY` (`XY` = two digits for sorting).

## Competency assessment

For each competency, select one:

1. **Meets expectations** – Clear evidence in the repository.
2. **Not yet met expectations** – Below pass standard; improvement required.
3. **Recycle** – Resubmission required within 5 working days.
4. **No evidence** – Nothing submitted / no contribution visible.

## Overall student grade

Each student receives one of:

- **Pass (P)** – Meets expectations in all competencies.
- **Concede (C)** – Not meeting all expectations; improvement needed to avoid future failure.
- **Fail (F)** – Failed this iteration.

Use judgement: if a student is strong overall but weak on one criterion, a Pass is acceptable in some cases.

## Iteration 3 – special rules

1. **Clear passes:**
   - No written feedback required (including self-reflection).
2. **At-risk students:**
   - Written feedback required (for records and disputes).
3. **Grades:**
   - Pass or Fail only (no Concede).
   - If unsure, mark Fail; fails will be reviewed.
   - Gradebook values: 0 or 2 only.
4. Do not post feedback to MS Teams or Blackboard.

## Feedback guidance

- Use Richard's GitHub Markdown bundler, but carefully—the summaries can be misleading.
- Feedback should be future focused.
- Always include:
  - What was done well.
  - What needs improvement.
- For poor performance, be explicit:
  - “You are currently failing / on track to fail.”
  - Clearly state what to focus on in future to turn it around.
- If recycle is required:
  - Give a specific deadline (date + time, within 5 working days).
  - Require the student to push changes or resubmit their self-reflection and notify you.
- Point students to course resources, not step-by-step fixes.
- Keep feedback brief. Students don't read long feedback.

## Recording grades

### 1. Review

- Complete all tables for teams and individuals.
- Ensure the student name and student number are entered.
- If marking Fail, add the student to the `Fail` spreadsheet.
- If the student is at risk, add them to the `At risk` spreadsheet.

### 2. Team feedback

- Paste the team feedback table into the MS Teams channel.
- Do not include the `Expectations` column.

### 3. Individual grades

- For students not participating, add a Fail grade.
- Enter the grade in the `Business model canvas` column (numeric only):
  - `2` = Pass
  - `1` = Conceded
  - `0` = Fail

### 4. Self-reflection grade

- Enter the grade in the `Self reflection 1` column:
  - `3` = Meets expectations
  - `2` = Not yet meeting expectations
  - `1` = Recycle
  - `0` = No evidence
- Iterations 1 and 2 only:
  - Paste individual feedback into the **Self reflection → Overall feedback** panel.

## Final checks

- Every student has:
  - A grade in Business model canvas.
  - A grade in Self reflection.
  - Feedback recorded for Self reflection.
- Students still enrolled but missing a self-reflection are graded appropriately.
